# Web UI

One page (`index.html`, `style.css`, `app.js`), plain HTML/CSS/JS with no build step, served by the API at `/`. It only talks to `/api/*` (see `api/README.md`). To host it on its own, set `apiBase` in `config.js` (see "Hosting the UI separately" in `api/README.md`). Run `uvicorn api.app:app` from the repo root and open http://127.0.0.1:8000.

This file is the visual guideline and the record of UI decisions. Each rule says which common problem in library search interfaces it avoids. Dated decisions are in `docs/decisions.md`.

## Brand

**It looks like Gutenberg, but searches better.** The look starts from gutenberg.org's own stylesheet (`gutenberg-globals.css` in [gutenbergtools/gutenbergsite](https://github.com/gutenbergtools/gutenbergsite)):
- the parchment header band
- Open Sans
- the teal pill search
- the red library section headings
- bold title, author, gray extra line in results

Users of the corpus already know that language. What we change is what's often wrong with library search interfaces: summaries in the results, explanations for matches, no walls of text.

**Name and attribution.** "Gutenberg Semantic Search" is a working name, set as a plain text wordmark. We don't use the Project Gutenberg logo. "Project Gutenberg" is a trademark and we're not affiliated, and the footer says so. Book data and covers link back to gutenberg.org.

**Light mode only for now.** Every color is a token on `:root`, so a dark set is a later addition, not a rewrite.

## Tokens

Never write a color outside the `:root` block in `style.css`. Each token has one job.

| Token | Value | Source in PG's CSS | Use |
|---|---|---|---|
| `--page` | `#ffffff` | `--main-bg-color` | page background |
| `--band` / `--band-line` | `#eceadf` / `#d9d5bf` | parchment `th` / menu border | header, footer, tags, cover fallback, status boxes |
| `--tint` / `--tint-line` | `#eef6f9` / `#dce9ee` | homepage shelf card | guide, "Why this book", detail panel |
| `--ink` | `#1f2428` | shelf title | primary text |
| `--ink-2` | `#3e444d` | | secondary text (summaries, meta in the panel) |
| `--muted` | `#5f6368` | `span.extra` (#757575, darkened) | captions; 6.0:1 on white, 5.6:1 on `--tint` |
| `--accent` | `#427e94` | submit button teal | search button, focus ring, pill borders |
| `--accent-strong` | `#23576b` | dark teal | link text (7.9:1 on white) |
| `--accent-soft` | `#c7dde3` | pill / hover wash | `<mark>`, hover fills |
| `--heading` | `#a01f13` | `--library-txt-color` | section headings and their 2px rule only, never body text |
| `--on-accent` | `#ffffff` | | text on the teal button (4.6:1) |

| `--class-1` to `--class-12`, `--class-other` | Tableau-style categorical | | book graph only: one colour per big LoC main class, grey for the rest |
| `--graph-edge` | `rgba(31, 36, 40, 0.1)` | | book graph links |

One accent hue (teal) plus PG's red for section rules. Don't add a color without checking contrast against the surface it sits on.

Spacing scale: 4, 8, 12, 16, 24 and 32px (`--s1` to `--s6`). Radii: 12px cards, 6px inputs, 4px buttons and covers, pills 999px.

## Type

- Open Sans (PG's font) from Google Fonts, falling back to Helvetica and Arial. Body 15px/1.5.
- Wordmark 20px/700. Result title 16px/700, underlined in a light rule that turns teal on hover (PG's `span.title`).
- Authors 14px ink. Meta 13px `--muted`, separated by space, never by a middle dot or bullet.
- Section headings 16px/700 red with a 2px red rule (PG's `.library h1`).
- `tabular-nums` only on scores.

## Writing rules

- **Label, don't explain.** Explanations live in the home guide and the "Why this book" box, not on every card.
- **Plain names.** Write "Matched in passage 3 of 6 from the book", never `doc_type=passage`. Write "Added to Gutenberg 2009", never `issued`.
- **Don't overclaim.** `issued` is labeled as the Gutenberg release year because it isn't the publication date. Summaries are labeled "auto-generated by Project Gutenberg" in the panel and footer. "Why this book" only shows what the search model itself scored, never literal word overlap, which would read like the model's reason when it isn't.
- **Escape everything from the data.** Titles, summaries and snippets go in with `textContent`. Highlighting splits text into text nodes and `<mark>` elements and never uses `innerHTML`.

## Layout and components

- **Search first.** The search box should be the most visible thing on the page. The pill search is the first thing under the header band, with no hero or featured carousel above it.
- **Two columns at 1024px and up,** so wide screens don't waste the right side. Results sit on the left (up to 640px) and a sticky detail panel on the right. The panel only appears once you pick a book. Below 1024px there's one column, and the panel opens as a full-screen sheet with a close button.
- **Home guide is always visible,** because semantic search works differently from the keyword search people expect. It holds one sentence on how to search, four example queries checked against the index, and one honest line on weak spots.
- **Result row.** Enough to judge a book without opening it: a summary and the subjects, not just a title.
  - Cover, title, authors with display names and roles ("edited by", "translated by").
  - "Added to Gutenberg" year (the release year; the data has no publication year).
  - Chips for the Library of Congress main class with its letter (e.g. "Political Science (J)", squarer corners) and the Gutenberg bookshelves (pills), both in a neutral outline. Both are filter buttons: clicking one shows the matching books, ranked by the current search if there is one, and jumps back to the top. Only one filter applies at a time: picking a class replaces the bookshelf and the other way round. A bar above the results shows the active filter with a × to clear it, and chips matching an active filter are highlighted. Blue fill only ever means "this filter is on", so no chip is blue by default. Filters are in the URL (`shelf=`, `lcc=`), so back and forward work.
  - Summary clamped to 2 lines, with a More/Less button right under it and a native `title` tooltip on mouse-over. It's never hover-only.
  - Up to 4 subject tags plus a "+N" button that shows the rest, so a row never becomes a wall of text. Tags wrap and never side-scroll.
- **Score + "Why this book" is one real button.** A relevance score that looks clickable should be, and a ranked list should explain why each book is there.
  - The raw score sits on the button. It opens a tinted box with the matched text. On first open it calls `/api/books/{id}/why`: the search model scores each sentence of that text, and the closest one is highlighted when the scores arrive. A one-line note says how to read the score.
  - The raw score stays, with no percentage and no cutoff. Scores aren't calibrated across queries (a nonsense query can still score around 0.4), so a percentage or threshold would claim more than we know.
- **Detail panel.** A key/value table, which is easier to read than a paragraph of metadata: (authors and roles, LCSH subjects, bookshelves, classification, added, link), then the full summary, contents and an introduction excerpt. Esc and the close button close it, and focus returns to the title that opened it. Nothing pops up on its own.
- **Paging.** 10 results and a "Show more" button. There's no count picker.
- **History.** Going back to a previous search must work, and the box must always show the query on screen.
  - The URL (`?q=&book=`) is the one source of truth. Every search and every opened book writes it, and rendering reads it, so back and forward work, links can be shared, and the box always shows the query on screen.
  - Recent searches (up to 6, in this browser only) drop down from the search box, with keyboard support and a clear button.
- **No gate before search.** Nobody has to answer a question or give feedback before searching. There's no intent question and no feedback widget yet.
- **Every state has a box.** Loading the model, no index (with the build command), API not running (with the start command), searching, no results, missing summary, and no extracted text.

## Interaction and accessibility

- `/` focuses the search box. Esc closes the panel or the recent list. Arrow keys move through recent searches.
- Everything clickable is a real `button` or `a`, focusable, with a 2px teal focus ring and hit targets of at least 24px.
- Nothing is hover-only. Secondary text uses `--ink-2` or `--muted`, never opacity, so secondary text stays readable.
- Result counts are announced once per search through a polite live region.
- `prefers-reduced-motion` turns off the chevron transition.

## Covers

Covers hotlink `https://www.gutenberg.org/cache/epub/{id}/pg{id}.cover.medium.jpg`, lazy-loaded, about 10 per page. A missing cover shows a parchment box with the title's first letter. Many older books only have Gutenberg's auto-generated patterned covers, which are louder than the rest of the page. We keep them because that's how the books look on gutenberg.org, and they make rows easy to tell apart. For an offline demo, every cover falls back to the letter box.

## Book graph page

`graph.html` (`graph.js` for the page, `graph-draw.js` for the canvas) shows the experiment in `graph/`: how the 1,000 books connect under each embedding model and similarity measure, coloured by LoC main class. It reads only `graph-data/`, which `python graph/export.py` builds, so it works without the search model loaded.

- **Map:** each dot is a book, placed by t-SNE on that variant's similarities, with faint links to its 3 nearest books. Class names sit on the islands where at least 8 books of a class cluster. A scattered class gets no label rather than a misleading one.
- **Arrange by LoC classes:** animates every book to the LoC layout and keeps the model's links. Links that cross between islands are where the model disagrees with LoC. Turned off under `prefers-reduced-motion`.
- **Side by side:** the LoC reference network next to the model's graph, sharing hover and selection.
- **A selected book:** its 10 nearest books are labelled on the map and listed in the side panel, with how many share its LoC class and how many LoC itself would pick.
- **Leaderboard:** every variant ranked by how often a book's 10 nearest books share its LoC class, with LoC itself and random links as the top and bottom references.
- **URL state:** `?model=&measure=&arrange=lcc&compare=1&book=`.
- **Keyboard:** "Find a book" picks a book, the neighbour list and leaderboard are buttons, and Esc clears the selection. The canvas itself is mouse and touch only.

## Before a demo

1. `python -m pytest tests/`
2. Run the four example queries against the current index and replace any whose top 3 isn't clearly on topic (`EXAMPLES` in `app.js`).
3. Take headless screenshots at 1280px and 390px of home, results, "Why this book" open, and the panel open. Check long titles, null summary, a book with no text, and the no-index and API-down states.
4. Do a keyboard-only pass: `/`, type, Enter, Tab to a "Why this book" button, Enter, open a title, Esc.
