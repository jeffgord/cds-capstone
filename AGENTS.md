# AGENTS.md

## Layout

- Docs: keep the root `README.md` to the bare minimum teammates need (what the repo is, setup, where the data is). Detail goes in a README in the relevant folder, e.g. `ingestion/README.md` for the field reference and how to build the dataset.
- `opensquare-reference/` — git submodule pointing at https://github.com/NYULibraries/KA-opensquare-research-project. Use it as a guide for this project; don't edit it.
- `ingestion/ingest.py` — script that builds the Gutenberg dataset in OpenSquare's shape: one flat `data/books/{id}.json` per book combining catalog metadata (`title`, `description` = Gutenberg summary, `topic_subjects`, ...) and extracted text fields (`table_of_contents`, `introduction`, `passages`, `conclusion`, `index_terms`). OpenSquare kept metadata JSON and one text blob (`textual_information/`) separately; the user chose one file per book over one big file. ID field is `gutenberg_id` (OpenSquare's was `isbnLibrary`). Run `python ingestion/ingest.py [--limit N]`.
- `ingestion/download_full_texts.py [--limit 25]` — saves full texts for the first N books of the same subset to `data/raw/full-texts/`, for inspecting the data. `ingest.py` reads from there when a text exists, otherwise downloads in memory without saving (user doesn't want all ~0.5 GB of texts locally, but does want some to look at). `download_full_texts.py` owns book selection (`wanted()`, `load_subset()`) and text fetching (`download_text()`); `ingest.py` imports them, so imports go one way only.
- `data/raw/` is gitignored; `data/books/` is committed so teammates get the dataset without running the scripts (~11 MB at 1,000 books). Rerun and commit it when ingestion changes. `data/raw/` holds the catalog CSV, the RDF archive and `full-texts/`. `data/books/` is wiped and rewritten on every run; `data/raw/` never is.
- Unlike OpenSquare (which prepended title, description, reviews and subjects to the text), the extracted-text fields hold only text from the book, kept separate from each other and from the metadata rather than one blob. The team plans its own embedding strategy and will pick and combine fields (and metadata) there. The passages and index terms haven't been validated as improving retrieval; they're there for the embedding team to test. Note that OpenSquare's search only embeds the text, so anything not combined in won't be searchable.

- `api/` — FastAPI server (`uvicorn api.app:app`): `/api/health`, `/api/search`, `/api/books/{id}`, and serves `web/` at `/`. Embedding-agnostic: a backend in `api/searchers.py` returns chunk hits (`gutenberg_id`, score, optional `doc_type`/`passage_index`/`text`); the API dedupes by book, pages, and builds every card from `data/books/` (`api/books.py`). Index location and model via `SEARCH_INDEX_DIR`, `SEARCH_MODEL`, `SEARCH_QUERY_PREFIX`. Contract in `api/README.md`.
- `web/` — the UI: one page, vanilla HTML/CSS/JS, no build step, talks only to `/api`. Visual guideline (based on gutenberg.org's own stylesheet, light mode only for now) and UI decisions in `web/README.md`. Never write a color outside the `:root` tokens in `style.css`; data strings go in via `textContent` only. The URL (`?q=&book=`) is the single source of truth for what's on screen.
- `docs/` — `ui-api-plan.md` (the plan), `decisions.md` (dated decisions: why, what was given up, source critique), `TODO.md` (now/next/later with owners, including notes for the index team). Add a decision entry when you change something a teammate or Charlene would ask "why?" about.
- `tests/` — `python -m pytest tests/`; uses a fake searcher, so no model or index is needed.

## Ingestion decisions and gotchas

- Subset: English nonfiction (no LoC class P, no "fiction" or "Periodicals" subject headings, no volume 2+), ordered by a SHA-256 hash of the ID so raising `--limit` only adds books. Not ranked by downloads: the RDF download counts are 30-day counts and a block of ~35 Feb–Mar 2026 releases (IDs ~78000) all show ~24.5k downloads from what looks like bot traffic.
- Metadata comes from `pg_catalog.csv`; the auto-generated summary (`pgterms:marc520`) comes from the RDF archive, which takes ~20s to scan, so `load_summaries()` caches all ~77k summaries in `data/raw/summaries.json` (88 MB, loads in 0.4s). Delete that file after re-downloading the archive, or new books get empty summaries.
- Texts come from the xmission mirror (`{d}/{i}/{g}/{id}/{id}-0.txt`, falling back to `{id}.txt`). `gutenberg.pglaf.org` was ~6s per file; gutenberg.org asks bulk downloaders to use mirrors. ~1.5s per book including a 0.5s politeness delay.
- START/END markers vary: some files have a BOM before `***`, some use `****`, older ones say "THIS PROJECT GUTENBERG". Mirror files have no license footer.
- There is deliberately no "last page" fallback for the conclusion section: nonfiction tails are footnotes, indexes, bibliographies or appendices, too varied to filter.
- Text samples are cleaned for embedding: prose unwrapped to one paragraph per line, paragraphs under 20 words skipped (title pages, headings, separators) along with digitization credits ("Produced by", "Transcribed", emails), `[Page N]`/`[Footnote]`/`[Illustration]` markers and `_italic_` underscores removed. ToC entries lose page numbers, dot leaders and "Chapter 1." / "CHAP. II.--" labels; a ToC ends at 3+ blank lines or a `* * *` separator line, capped at 10 pages (Summa Theologica's ToC runs straight into the text; Livingstone's 1039 has a genuinely ~38k-char ToC that the cap truncates). Headings may be in `_italics_` (53477's `_Contents_`), and page numbers may be labelled (`_Page_ 1`). Of the first 25 books, the 10 without a ToC really have none in the text (one is only an image). Roman numerals in ToC labels are matched uppercase only so words like "Mill." survive.
- Passages: ~400 chars from 6 evenly spaced points between the ToC and the body end (the index heading, else 90% of the book). The conclusion search is NOT cut at 90%, only at the index: conclusions usually sit in the last 10%. Index: last INDEX heading in the final 30% (Merck's 1899 Manual has an index at the front); top level = the first entry's indentation; deeper lines are sub-entries (skipped) and a shallower line ends the index (ads and transcriber notes follow some indexes). Terms are sampled evenly to ~1 page so they aren't all "A".
- `strip_boilerplate` also cuts an "End of the Project Gutenberg EBook" footer line found in older files before the END marker.
- Survey of the first 100 books (2026-11-11, script kept outside the repo) found and fixed: prefaces usually come *before* the ToC, so the intro search runs from the start of the book, skipping matches inside the ToC (intro headings found: 33 → 74 of 100); headings with extra words ("AUTHOR'S PREFACE.", "V. CONCLUSION--…", "ALPHABETICAL INDEX OF NAMES") match as all-caps lines, except title-page credits ending in "BY"; 3+ blank lines right after a CONTENTS heading no longer end the ToC immediately; paragraphs over 5% digits (tables, errata, illustration lists) and transcriber notes are skipped; "indexes" with under 10 terms are dropped; `pp. 1-5` page refs are stripped from ToC entries. Coverage after: ToC 68, intro heading 74, conclusion 12, index 26, 6 passages 97 of 100. The books without a ToC were checked by hand and have none in the text.
- Known leftovers not worth fixing: missing drop-cap first letters ("f all the various..."), ditto marks and "DESIGN NO. 1"-style lines in some ToCs.
- Don't use the `Gutenberg` PyPI package: archived, pins old rdflib/pyparsing, needs Berkeley DB.
- Ingestion and embedding deps are in `requirements.txt`; API and test deps are in `api/requirements.txt`. Install into `.venv/` (gitignored; local setup verified with Python 3.13). Run scripts with `.venv/bin/python` or after `source .venv/bin/activate`. Progress bars go to stderr; skip messages use `tqdm.write` so they don't break the bar.

## Reference repo notes

- Its ingestion is not one pipeline: `ingestion/ingestion_pipeline.py` only fetches metadata and merges subject headings. The rest (`download-pdfs.py`, `extract-text-from-pdfs`, `metadata_exporter.py`, `concat_text.py`) are standalone scripts with hardcoded Windows paths, run by hand in that order. Then `embedder/embedding_pipeline.py` builds the FAISS index.
- It embeds a per-book "profile" (description, reviews, subject headings, ToC, one intro page, one conclusion page), not full text. Chunk size is 128 *characters*.

## Setup

- Clone with `git clone --recurse-submodules <url>`, or after a plain clone run `git submodule update --init`. Otherwise `opensquare-reference/` is empty.
- To pull upstream updates to the reference repo: `git submodule update --remote opensquare-reference`, then commit the changed submodule pointer.
